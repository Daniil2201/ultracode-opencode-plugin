# afd-method

## Что такое AFD

Методология, где сначала строятся tools, которыми будет пользоваться агент. Валидация — через взаимодействие с ИИ, не через UI. Потом детерминированные операции выносятся в API. Потом UI для человека.

## Принцип Zero-Gap Deployment

Создание tool для агента = его развёртывание. Не нужен UI, не нужен API — агент уже работает.

## Четыре этапа

1. Tools — парсеры, генераторы, валидаторы. То, чем агент пользуется.
2. Валидация — гоняем агента на реальных данных, смотрим что работает.
3. API — HTTP/CLI для детерминированных операций.
4. UI — HTML/CSS/JS для человека.

## Когда применять

Проекты, где есть сложная логика или данные. Игры, сервисы, инструменты.

## Когда не применять

Простой проект (лендинг, маленькая утилита) — AFD избыточен, делаем напрямую.

## Как влияет на планирование

При чтении `TZ.md` раздел «Этапы (AFD)» — приоритетный. Агент идёт по нему. Если раздела нет — предлагает создать через `/tz-refine`.
