# browser-autopilot — автономный режим в реальном браузере

Режим «как Claude»: пользователь даёт ОДИН запрос (цель), и агент сам:
смотрит страницу → решает следующий шаг → действует в реальном Firefox →
снова смотрит → … → до завершения цели. Без подсказок, без вопросов на каждом
шаге, в реальном времени.

## Когда использовать
Любая задача в браузере: «начни игру и собери данные», «пройди регистрацию»,
«проверь магазин и выпиши цены», «найди X и сделай Y», «автономно обойди
сайт», «заполни форму», «собери структуру». Включается автоматически при
запросе действия на сайте/в вебе.

## Триггер, который надо проверить первым
1. Сними `browser_snapshot` активной вкладки — это и проверка канала, и первый взгляд на страницу.
2. Если вернулось `{error} NO_EXTENSION` — opencode уже молча откатился на
   Playwright (свой Firefox, сессия пользователя не видна). Скажи в ОДНОЙ
   строке: «работаю в фоновом Firefox (расширение не подключено). Вернуть
   твой браузер: запусти `node src/bridge.js`, в about:debugging Reload
   OpenFox, проверь `curl http://127.0.0.1:5678/health` → extensionConnected:true».
   Задачу продолжай на Playwright — не висни.
3. `EXT_TIMEOUT` — просто повтори вызов (страница могла быть занята).
4. Работай по данным страницы: `browser_snapshot` (роли+селекторы+имена) +
   `browser_read_text` (компактный текст).

## Политика «активная вкладка» — жёсткое ограничение
- Агент действует ТОЛЬКО в активной вкладке браузера пользователя. Инструментов
  «открыть URL», «закрыть вкладку», «список вкладок», «переключить вкладку»
  НЕТ и быть не может.
- Нужная страница не открыта или ты оказался не там — НЕ пытайся открывать/переключать.
  Скажи пользователю одну строку: «открой такую-то страницу в активной вкладке, и я продолжу».
- Навигация доступна только по истории активной вкладки: `browser_navigate_back` /
  `browser_navigate_forward` / `browser_reload`.

## Цикл (сердце режима)
Пока цель не достигнута (макс ~40 шагов на запрос):
1. **Наблюдай.** `browser_snapshot` (компактно) или `browser_read_text`.
   Сокращай вывод: тебе нужны элементы для действия и доказательство прогресса,
   а не весь HTML.
2. **Решай сам.** Что приближает к цели? Клик по кнопке из snapshot
   (role/name/selector), ввод в поле, или navigate_back/forward по истории.
   evaluate вместо клика, когда клик ненадёжен. НЕ спрашивай пользователя на этом шаге.
3. **Действуй.** `browser_click`/`browser_type`/`browser_press`/`browser_scroll`/
   `browser_wait`/`browser_evaluate`.
4. **Переживи навигацию.** После сабмита/перехода content-script перезапускается,
   результат предыдущего действия теряется. Поэтому ПОСЛЕ действия, которое
   уводит со страницы: `browser_wait` на элемент, который обязан появиться на
   следующей странице (или повторный `browser_snapshot`), и только потом следующий шаг.
5. **Проверь, что прилипло.** Страница не изменилась после клика → элемент
   перехватил событие по-другому: попробуй `browser_evaluate`
   (`el.click()`), press Enter/уточнённый селектор. Не бей по одному месту
   трижды — смени подход.
6. **Сверяйся с целью** каждые 3–5 шагов: запиши в 1 строку, что уже сделано
   и что осталось. Держи прогресс снаружи разговора (todowrite / короткая
   заметка), чтобы «потеря контекста» не убивала ход.
7. **Остановись и отчитайся**, когда: цель достигнута (собери доказательство),
   цель недостижима (нет такого элемента/доступа — сообщи факт), или шаги
   исчерпаны (расскажи, где упёрся и что попробовать дальше). Не цикли бесконечно.

## Правила выбора селекторов
- Сначала селекторы/имена из `browser_snapshot` (роль + имя + selector/href).
- Текст-кнопки: `browser_evaluate` с поиском по тексту
  (`[...document.querySelectorAll('button,a')].find(e => e.textContent.trim()===Т)?.click()`)
  — надёжнее, чем клик с угаданным css.
- Значения (цены, статы, счетчики): `browser_evaluate` возвращает JSON-safe
  результат — читай числа прямо из DOM.
- Чекбоксы/капча: `browser_evaluate` (`el.checked=true; el.dispatchEvent(new
  Event('change',{bubbles:true})); form.submit()`), потом `browser_wait` следующей страницы.

## Завершение = доказательство, не слова
- Цель достигнута: верни структурированный итог (что сделал + факты/данные,
  которые добыл, с URL). Полезные данные — в отчёт `reports/*.md` в проекте.
- Каждая значимая победа/неудача — одна строка в журнал
  (`ultracode_context action=add kind=progress text="<что> — <факт>"`), чтобы
  следующая сессия продолжила с места.

## Человеческий профиль (анти-бот) — соблюдать всегда
- Клики/ввод уже идут через человеческий слой исполнителя (случайные паузы 200–700мс, посимвольный ввод 25–80мс/символ, докрутка до видимого элемента). НЕ обходи его: не делай «клик в 0 мс» через evaluate, если можно обычным кликом.
- Не долби одно и то же трижды подряд — смени подход (иначе это выглядит как бот-ретрай).
- После каждого навигационного шага — `browser_wait` (и пауза). Не переходи страницу за страницей без остановки: раз в 3–5 шагов чуть прочитай страницу перед действием (это и прогресс, и человеческий ритм).
- Не создавай и не повторяй действия с частотой > 1 в 2 секунды. Для массовых операций (обход 20 разделов) работай маленькими сериями.
- Скорость важнее красивой «чистки»: 40 шагов на запрос = потолок, но лучше 20 медленных, чем 40, которые похожи на скрипт.
- Единственная легальная «машина» — `browser_evaluate`: для ЧТЕНИЯ значений (цены, статы, счётчики). Для действий — обычные browser_click/type.

## Чего не делать
- Не спрашивать после каждого шага (только если цель реально двухсмысленна —
  тогда 1 вопрос с дефолтом, и продолжай).
- Не копировать скриншоты по 500 КБ в контекст без нужды — только base64 для
  скринов-доказательств по запросу, текстовый снапшот обычно достаточно.
- Не читать `config.toml`, не трогать секреты, не удалять файлы без разрешения.
