description: "Планирует большую задачу с измеримым условием, профиль balanced"
---

Целевой цикл: продолжать работу, пока условие не станет измеримо истинным. Явная точка входа оркестрации — только `/goal` создаёт план, обычные запросы план не создают.

> `ultracode_context action=budget profile=balanced` — профиль порогов этой сессии (перетирает ручные, приоритет за последним вызовом).

## Usage

```
/goal <цель>
```

## Instructions

Выполни для заданной цели:

1. **Одна конечная цель** — что именно должно стать истиной (измеримо). Плохо: «доделать сайт». Хорошо: «все тесты в farm/ проходят, clippy чистый».
2. **Метод проверки (acceptance.command)** — как убедиться, что условие выполнено (команда, quality_check, чтение файла). Зафиксируй ДО реализации. Проверка после завершения шага через evidence, а не после каждого edit.
   Дефолт: если в сессии виден `<ultracode-stack>`, используй его test-команду, пока пользователь не задал свою. Явно переданная команда всегда важнее автоопределения.
3. **Ограничения** — чего не делать (файлы не трогать, config.toml не открывать, порог не снижать, scope не расширять на несвязанные баги).
4. **Лимит** — не более 20 итераций, до 3 попыток на шаг.

Классификатор (hint, не триггер): `simple | multi_step | design | research | bugfix` — см. `.opencode/lib/ultracode/classifier.ts`. Не запускай оркестрацию скрыто по ключевым словам и не запускай Open Design только из-за слова «дизайн».

Цикл:
- Разбей цель на шаги → сохрани в контекст-стор (ultracode_context `plan_new`). План: `goal → plan → tasks → implementation → evidence`.
- Независимые шаги запускай параллельно одним сообщением через `ultracode_delegate` (каждому `planId` + `stepId`), `maxParallel=3`. Встроенный `task/subagent` как скрытый fallback не использовать. Зависимые — только после предшественников (`dependsOn`).
- **Перед использованием любой библиотеки** — проверь её реальную версию и API (npm view / типы в node_modules), не пиши код из памяти (см. Dependency discipline агента).
- Выполняй шаги, отмечай `plan_step`; `done` только с успешным evidence (`/verify`), без evidence шаг остаётся `verify_required`.
- После ошибки повтори шаг (до 3 попыток), затем сохрани blocker и останови план с явным blocker.
- Не спрашивай подтверждение между обычными шагами внутри scope. Спрашивай только blocking question или перед внешним/необратимым эффектом (удаление, публикация, миграция, секреты, массовое изменение, Open Design run). Максимум 3 вопроса за раз.
- Достигнут лимит → покажи оставшуюся работу и спроси пользователя (продолжить/бросить/сменить условие).
- «Стоп» прекращает активный план. Несвязанный найденный баг не чини автоматически.

Завершение: результат → изменённые файлы → evidence (команда + exit code + обрезанный вывод) → допущения → blockers.

Самообучение: после успеха или неудачи запиши урок в контекст-стор:
`ultracode_context learn kind=success|lesson text=...` — уроки инжектятся в следующие сессии.
