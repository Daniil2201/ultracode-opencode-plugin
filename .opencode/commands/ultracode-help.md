Справка по Ultracode: команды, которые реально существуют.

## Usage

```
/ultracode-help
```

## Команды

**Оркестрация и метод:**

- `/goal <цель>` — явная оркестрация: план → parallel task → evidence. Единственная точка создания плана.
- `/bolt <slug>` — короткий болт: до 3 шагов с acceptance, требует spec-файл.
- `/spec <цель> [slug]` — спецификация в `spec/<slug>.md` до начала кода.
- `/verify <команда>` — evidence-gate проверка шага (exit 0 → done, иначе failed).
- `/design <задача>` — явный Open Design workflow (brief → confirm → start_run → manifest).
- `/debug <симптом>` — системный дебаг: reproduce → гипотезы по одной → fix → регресс-тест → verify.
- `/checkpoint` — компактный checkpoint плана перед compaction, без дублей.
- `/status` — план + видимость контекста + токены + ферма + пороги, профиль и handoff.
- `/evaluate [smoke|all]` — лабораторная оценка (gates + score + report).
- `/ultracode-help` — эта справка.

**ТЗ (SDD):**

- `/tz-init` — создаёт `TZ.md` из шаблона в текущем проекте.
- `/tz-check` — проверяет `TZ.md`: полнота, противоречия, реализуемость.
- `/tz-refine` — дорабатывает `TZ.md`: вопросы по дырам, точечные правки.

**Ферма и контент (tg-manager MCP):**

- Глобальные команды (в `~/.config/opencode/commands/`, доступны и вне этого проекта): `/farm` — состояние фермы, `/farm-connect` — подключение к контексту, `/farm-update` — обновление установки.
- `/generate` — пост в стиле донора без публикации; `/check` — quality gate текста.
- `/publish` — публикация готового поста; `/fetch` — история канала; `/learn` — изучение стиля канала.

**Память (контекст-стор `ultracode_context`):**

- `/recall` — поиск по прошлым сессиям и урокам; `/remember` — сохранить инсайт.

**Под капотом (вызывает модель, не пользователь):**

- `ultracode_context` — единый tool со множеством экшенов (`list`, `add`, `search`, `view`, `plan_new`, `plan_show`, `plan_step`, `learn`, `lessons`, `stats`, `tokens`, `budget`, `handoff` и др.). Вызывается агентом напрямую (persist решений, планы, evidence, уроки) и командами выше — не через слэш-команду.

**Правила:**

- Не расширять scope на несвязанные баги.
- Подтверждение только перед необратимым/внешним (удаление, публикация, миграция, секреты, массовое изменение, Open Design run).
- Максимум 3 вопроса за раз.
