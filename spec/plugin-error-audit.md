# Аудит дефектов Ultracode plugin

## Объём и достоверность

- Дата: 2026-10-25. Объём: `.opencode/plugin/ultracode.ts`, напрямую используемые `lib/ultracode`, тесты/команды/агенты и SDK 1.18.27. Отдельно помечен соседний `agentmemory-capture.ts`.
- Режим: read-only; код и существующие незакоммиченные изменения не изменялись. На старте worktree уже был dirty, в том числе `plugin/ultracode.ts`, `prune-store.ts`, `spec/context-pruner.md` и `CHANGELOG.md`; текущие изменения pruner диагностики учтены.
- CodeGraph в этой сессии недоступен; использованы типы установленного SDK, чтение исходников и независимые read-only проверки `explore`, `reviewer-error-boundaries`, `reviewer-contracts`, `reviewer-security-regression`.
- **Живой сбой плагина не воспроизведён.** Snapshot `.saropa/diagnostics/history.json` от 2026-10-03 имеет 0 ошибок, но он не проверяет текущие пути. Ниже — source-confirmed дефекты/риски и пробелы тестов, не утверждение, что каждый уже проявился у пользователя.
- Acceptance прогон этого аудита: `node --test .opencode/tests/*.test.ts .opencode/tests/runtime/*.test.ts .opencode/tests/adversarial/*.test.ts` завершился с exit 0; TAP summary — 349 total, 346 pass, 0 fail, 3 skip. Три skip относятся к отсутствующему farm binary. В output также были две строки `fatal: not a git repository` без падения тестов; источник не атрибутирован и не считается подтверждённым plugin-дефектом. Полный per-test output не сохранялся. Зелёный suite не покрывает описанные ниже failure paths.
- Runtime сейчас: `opencode v2.0.32`, установленные `@opencode-ai/plugin` / `@opencode-ai/sdk` `1.18.27`.

## Риски, не подтверждённые как дефекты

1. `store.ts:63-79` при миграции legacy global store создаёт per-project store и переносит только global knowledge, не весь `config`. Это может быть намеренной изоляцией проектов; не менять без решения, какие из старых `budgetTokens/anim/modelLimit` должны наследоваться.
2. На момент проверки runtime `opencode v2.0.32`, package SDK/plugin `1.18.27`; запуск OpenCode, который якобы переписывает `.opencode/package.json`, не выполнялся. Совместимость session API требует smoke-теста в disposable copy.
3. `metrics.jsonl` сейчас содержит generic `tool=skill`, а skill name пишется в context knowledge. Для dispatch-аудита выбран существующий JSONL-поток; отдельный stream не нужен.
4. Решение «acceptance только через команды» принято 2026-10-25: per-step check = exit code команды, file/line verifier исключён (LLM-галлюцинации на строках).

1. Сначала закрыть security/data-loss P1 (SEC-01..03, DATA-01..03) и retry-дефект Budget Manager (BUDGET-01).
2. Затем закрыть step acceptance producer/consumer gap (PLAN-01) и добавить `ultracode_delegate` по `spec/subagent-model-routing.md`.
3. Проверить контракт usage (`BUDGET-03`) на runtime v2.0.32; `BUDGET-02` и остальные P2 остаются backlog до принятия их в implementation scope.
